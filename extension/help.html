LINKEDIN FEED GUARD · BETA

Keep the feed intact. Reduce unnecessary work.

LinkedIn Feed Guard is a local beta for Brave and Chromium browsers. It does not delete posts, reload pages or suspend tabs. It is not affiliated with LinkedIn.

Install or update

Extract the package to a permanent folder. Open brave://extensions (chrome://extensions in Chrome), enable Developer mode, and load the extension folder that contains manifest.json. To update in place, replace files in your existing extension folder and click Reload. Save drafts and reload LinkedIn tabs afterwards. Do not run two copies together.

English and Italian

Use the language selector here or in the popup. Browser default selects Italian for an Italian browser interface and English otherwise. Your choice is stored locally and shared between the popup and this help page. Extension names in the browser follow the browser language.

How detection works

The extension recognizes mainFeed containers, component-key list items, supported feed-card markers, and a cautious list-item fallback with an expandable-text-box marker. It handles late-loading containers and attribute changes. It does not treat every article, list item or occurrence of a word as a post.

If the counter stays at zero

Open https://www.linkedin.com/feed/, wait for actual posts, scroll slightly and choose Rescan page. If the counter is still zero, open Diagnostics. Inspect the report and copy it manually when reporting a problem. A zero count means post rendering and video optimizations are not operating on detected posts; a feed container alone is not proof of success.

Scope and safe handling

Page and video changes operate only on the main feed (/feed or /feed/). Messaging, profiles, jobs and individual-post pages are excluded. The script is registered on www.linkedin.com so it can detect in-page navigation back to the feed. Frames and shadow-DOM feeds are not supported. The optional network filter applies across www.linkedin.com.

Deferred rendering

Distant cards may receive content-visibility: auto, with a measured intrinsic height. Cards with focus, editors, input fields, open menus or playing media are excluded. The browser can skip rendering, but post nodes and application state remain in memory. No RAM or CPU limit is imposed. Turning the feature off removes its annotations.

Video behavior

Videos in detected posts may be paused when off screen or when the tab is hidden. Fullscreen and picture-in-picture playback are excluded. The extension never resumes playback or changes media URLs, volume or account settings. Pausing does not guarantee that buffering or memory allocation stops.

Long-feed memory warning

Every post you scroll past stays in the page: LinkedIn's infinite feed only grows, and a renderer that runs out of memory shows "Aw, Snap!". Deferred rendering and video pauses reduce work but cannot release that memory; only a reload does. When the feed reaches 200 detected posts, or the browser reports more than 1200 MB (or half of the limit) of JavaScript memory in use, a small notice in the corner offers Reload feed or Later. Later waits for 100 more posts or 25% more memory. The extension never reloads by itself; save drafts first. The popup shows the current JavaScript memory and has the same Reload feed button. The measurement is Chromium's coarse performance.memory value, not the whole tab's memory.

Optional network filter

The experimental, disabled-by-default rule blocks XHR/fetch, beacon and image requests to https://www.linkedin.com/li/track and its query or path variants, initiated by www.linkedin.com. It is not a complete tracker blocker or a replacement for Brave Shields. Blocking requests can cause retries or break site behavior. Keep it off during initial testing.

Privacy and permissions

Only six on/off settings and one language preference are stored in local extension storage; no Sync storage is used. Per-tab counts are held in memory. Diagnostics contain the version numbers of the popup and of the page script, fixed status codes, whether Feed Guard is enabled, whether the browser supports deferred rendering, aggregate post, video and selector counts, and JavaScript memory in 50 MB steps; they exclude text, HTML, input values, account IDs, component-key values, titles, URLs, cookies and browsing history. Diagnostics are generated only on request and copied only when you choose to copy. No telemetry, external server, remote scripts or automatic update endpoint is configured.

Permissions are storage and declarativeNetRequestWithHostAccess, restricted to https://www.linkedin.com/*. There are no clipboard, cookies, history or debugger permissions. A content script still has technical access to the permitted page DOM; privacy depends on the implementation, not just the permission list.

Disable and remove

The master switch removes rendering annotations and disables the optional filter. Already paused videos remain paused. If you disable, remove or reload the extension from the browser extensions page, save drafts and reload LinkedIn to clear any previous script instance. Do not disable browser security or organizational policies.

Validation and limitations

Automated tests use local synthetic DOMs, real browser layout and media, and simulated extension APIs. This package has not been tested in your authenticated LinkedIn session. Browser policy prevented installation in the test environment, so installed-extension behavior and the DNR engine still need manual testing. No RAM savings, crash fix or support for every LinkedIn layout is guaranteed.
